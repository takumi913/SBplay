# 104 · 稳定性缺口四项：失败可见性、模式收敛、USB 拔出广播、首帧看门狗（2026-11-07，未上机）

> README「有线 / 无线稳定性缺口」列了四项：首帧看门狗、USB 拔出广播、失败可见性、模式收敛。
> 本篇记录四项的改法。**四项都只过了 CI（构建、全量单测、NewApi lint），必须上机复验。**
> 第四项“首帧看门狗”按字面是计时器，和 AGENTS.md §2“不要用计时器判断连接失败”冲突；
> 车主选择了“只用事件”的做法，见 §4。

起因：2026-11-07 一位车主（领克 02 / CS11 固件，美版 iPhone 17，iOS 26.5.1）有线、无线都连不上，
首页只显示“未发现 iPhone”，报告写 `Connection: wireless` 而日志是 `transport=wired`，看不出卡在哪一步。

## 1. 失败可见性（`ConnectionAttemptRecord`，提交 5748c9f + a8045c0 的编译修复）

- 失败原因以前只画在后台的 CarPlay 主机界面上；会话一结束首页就退回固定文案。
  主机界面关闭时会结束整个进程，所以记录**落盘**到 SharedPreferences `diplay_connection_attempt`。
- 事件：主机界面实例第一次 `startCarPlay` → 新记录（同一实例内的自动重试保留已记下的失败）；
  每个状态 → 记“停在哪一步”；`CarPlayStatus.Failed` → 记原因；会话建立 → 删除；`shutdown()` → 标记正常结束。
- “被中断”= 记录仍是进行中，但写记录的进程号不是当前进程（上一个进程在连接途中没了）。是事件，不是超时。
- 首页圆环下：“上次连接失败 / 上次连接被中断”；操作卡片：方式 · 时间 · 停在哪一步 + 截断 80 字的原因。
- 诊断报告：`--- Last connection attempt ---` 一段，完整原因。原因和步骤先过 `DiagnosticRedactor`。

## 2. 模式收敛（`ConnectionModePolicy`，提交 a8045c0）

- 以前三份状态：首页标签（点了不保存）、保存的模式（自动连接、蓝牙唤起、热点自动开启、报告读它）、
  主机界面的 `wirelessEnabled`（**每次回到前台从保存的模式重读**）。
- 规则：有会话时以会话实际传输方式为准（主机在每次控制器启动时 `CarPlayProgress.publishTransport`，
  `shutdown` 时清除）；没有会话时以保存的模式为准，点标签立即保存。
- 会话进行中**绝不改保存的模式**：否则主机下一次自动重试会悄悄换成另一种连接方式。
  此时点另一个标签只提示“请先断开再切换”。
- 报告拆成 `Connection (selected mode)` 与 `Session transport` 两行。

## 3. USB 拔出广播（`WiredDetachPolicy`，本篇所在提交）

- 以前只监听插入（`registerAttachReceiver`），拔线只能等 USB 读取出错。API 19 的 `requestWait()` 无超时，
  日志里也没有一行明确写“线被拔了”。
- 现在有线控制器注册 `ACTION_USB_DEVICE_DETACHED`，每个 Apple 设备的拔出都记一行稳定口径：
  `STEP usb/detached: device=<节点> phase=<阶段> decision=<决定>`。
- 只有 `DATAPATHS` / `CONTROL` 阶段、拔出的正是正在用的设备节点、且不是我们自己拆会话触发的重新枚举，
  才 `fail("iPhone USB cable unplugged (USB_DEVICE_DETACHED)")`——和读取出错是同一条失败路径，
  之后照旧由宿主自动重试、等待重新插上。
- 不处理的情况：更早的阶段（切 CarPlay 配置、软件重插本来就会断开再接入）；
  `requestWiredReenumeration` / `detachWiredForReconnect` 已置 `teardownDetachExpected`；其它 USB 设备。
- 已知限制：拔线时读取失败和拔出广播谁先到不确定，首页“上次连接失败”的原因可能显示
  `USBMUX read failed` 而不是 `unplugged`；以日志里的 `STEP usb/detached` 为准。

## 4. 首帧看门狗（只用事件，本篇所在提交）

- 现象：会话一建立，主机就把 CarPlay 画面切到前台；iPhone 不发画面时，车主看到的只是黑屏，首页还显示“已连接”。
- 原想法“等第一帧渲染出来再切到前台”**做不到**：解码器必须有可见的画面表面才渲染（`AndroidMediaSink`：
  没有表面时什么都显示不了），而主机退到后台时 TextureView 表面会被销毁（日志 `Texture surface destroyed`）。
  在后台等第一帧会永远等不到。
- 现在的做法（全部是事件，没有计时器，不自动断开）：
  - 会话建立（`onSessionActive`）照旧切到前台，同时在黑色画面上盖一层提示“已建立会话，正在等待 iPhone 发送画面”，
    带“返回首页”“断开连接”两个按钮；提示层本身不拦截触摸，三指手势和 CarPlay 触摸照常。
  - 第一帧渲染（`onVideoFrameRendered`，控制器保证每个会话只报一次）→ 提示消失，连接记录删除。
  - 会话结束、重建、`shutdown` → 提示消失。
  - “断开连接”按钮先回首页，等主机进入后台（`onStop` 事件）再停会话，和从首页断开走同一条路——
    主机在前台被关闭会结束整个进程（`onDestroy`）。
  - 首页：会话已建立但没出画面时，标题和状态显示“等待画面”，圆环下显示同一句等待提示。
  - 连接记录：会话建立不再删记录，而是记“已建立会话、等待画面”；第一帧才删除。没出画面会话就结束（或进程没了），
    首页显示“上次连接没有画面”；之后的自动重试把它保留为失败原因“上一轮会话已建立，但没有收到 iPhone 的画面”。
  - 日志口径：`STEP video/await-first-frame`、`STEP video/first-frame`、`STEP video/no-first-frame`。
- 无线已有的 45 秒交接看门狗（`WIRELESS_HANDOFF_TIMEOUT_MILLIS`）是早先就有的代码，本篇未改动。

## 上机复验清单

1. 无线、USB 各失败一次：首页应显示“上次连接失败”和停在哪一步；报告里有 `Last connection attempt`。
2. 连接成功后断开：首页不应显示失败。
3. 切换标签后退出再进：标签保持；有会话时点另一个标签应只弹提示。
4. 有线投屏中拔线：日志出现 `STEP usb/detached ... decision=END_SESSION`，首页转为等待 USB；重新插上能自动恢复。
5. 有线投屏中点“断开连接”：日志里的拔出应为 `decision=IGNORE_TEARDOWN` 或 `IGNORE_CLOSED`，首页不报失败。
6. 会话建立后到第一帧之间：画面上应出现等待提示，出画面后自动消失；首页此时显示“等待画面”。
7. 在等待提示上点“断开连接”：应回到首页且应用不退出，首页显示“上次连接没有画面”。
8. 正常出画面后断开：首页不应显示任何失败或“没有画面”。
